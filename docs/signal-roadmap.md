# 信号源路线图:从技术圈雷达到付费需求雷达

> 2026-08-11,来自 daily-ten 选品调研首轮实战的方法论修正(Yuan 的三条 insight)。

## 为什么要转向

1. **付费意愿排序:大众 > prosumer > 开发者。** 现有四源(HN / Reddit / V2EX / GitHub)全是开发者自留地——付费意愿最低、最爱自己写免费工具并开源的人群。用这套语料选品,筛出的品类天然落进"免费开源绞肉机"。实证:首轮 306 卡筛矿,最强集群「AI coding 成本看板」细拆后,7 张卡里 0 张指向独立付费产品空间(2 张是给免费开源工具提的 feature request、1 张提给官方 repo、1 张灰色中转)。
2. **看存量 app 找需求是方法论错误。** 只会得出两种结论——"这条路不行"或"这条路拥挤",本质是抱着已存在的解决方案去找问题;盲区 = 需求存在但尚未被产品化的地方,而那正是机会所在。需求发现必须挖**需求侧原生信号**。
3. **"真实成交"不必来自同品类产品的销量。** 人肉服务成交是更干净的需求侧付费铁证:Fiverr/Upwork 上有人为一个重复性小任务真金白银付 $5-50,gig 评价数就是公开成交代理——既证明付费意愿,又不预设解法形态。

## 新信号源(按优先级)

1. **Fiverr / Upwork gig 成交挖矿**(需求侧付费信号,最硬):高频重复小任务、单价 $5-50、评价数高 → 候选"可自动化的人肉需求"。抓取走公开类目页 + gig 评价数;注意反爬,低频抓取。
2. **搜索缺口**:Google / App Store 自动补全里的 "how to X without Y" 长尾查询;Google Trends 上升查询。搜的人多、答案烂 = 未满足需求。
3. **TikTok Creative Center**(公开数据,无需爬 TikTok 本体):广告热词与爆款品类,作为大众关注度代理指标。
4. **workaround 内容**:YouTube/TikTok 上"用三个 app 拼出 XX"类教程的播放与评论热度(评论区"求 app 名"的密度是强信号)。抓取难度高,可后置或先人工。

## 现有源与筛选逻辑的已知偏差(首轮筛矿实测)

- **github 占 81%**,且多为宿主项目的 feature request:需求真实,但独立产品化空间被宿主吸走 → 建议卡片加「宿主依附度」字段(LLM 判断:该需求是否只有宿主项目适合做)。
- **HN score 抓取过早**(普遍 1-6 分,热度未发酵)→ ingest 后 24-48h 回填一次 score。
- **reddit 仍为 0**(公开 .json 端点 403,需注册 OAuth app 走官方 API)。
- **paySignal 不应是唯一入口**:weak 池里有 148 评论(剪贴板)和 137 评论(截图软件差评)的高热卡 → 看板加热度排序维度。
- 新方法论下最有分量的新字段:「**人肉成交证据**」——该需求在 Fiverr/Upwork 是否存在对应 gig 及其成交量级。

## 不变的

四段管道架构(抓取→过滤→提炼→存储)不变;新源只需各自实现 `fetchCandidates(): Promise<Candidate[]>` 即可插入。
